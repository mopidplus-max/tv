# SIMPLE IPTV

Локальный интернет-телеканал на Python + Flask для Windows. Один общий HLS-поток формируется единственным эфирным движком FFmpeg; зрители подключаются к нему через браузер, hls.js или IPTV-плеер. Панель администратора скрыта по отдельному адресу.

## Возможности

- Единый эфирный движок: один FFmpeg-процесс на весь канал, без процесса на каждого зрителя.
- Источники: локальные файлы, прямые HTTP/HTTPS, HLS и ссылки, которые разбирает yt-dlp.
- yt-dlp используется **только для извлечения прямого URL**. Оригинальные видео не скачиваются.
- Адаптивное зондирование FFprobe, режимы COPY/TRANSCODE, масштабирование без растяжения, чёрные поля, обработка отсутствующей аудиодорожки.
- Логотип PNG 342×74: правый верхний угол, пропорциональное масштабирование.
- Передачи из последовательных видео, бамперы и реклама после роликов/передач, случайный выбор без немедленных повторов.
- Расписание, повторяющиеся выходы, автоматическая ротация, EPG `/epg.xml` и `/epg.xml.gz`, M3U `/playlist.m3u`.
- Режимы канала: `on`, `off`, `maintenance`. В профилактике приоритет: видео → изображение + музыка → брендовая заставка.
- Скрытая админ-панель: Argon2id, CSRF, ограничение попыток входа, безопасные сессии.
- Мониторинг CPU/RAM/диска/сети, статистика HLS, журнал эфира, диагностика и тестовая генерация HLS.
- Публичные страницы не содержат ссылок и упоминаний адреса админ-панели.

## Требования

- Windows 10/11, Python 3.11+ (проверено на 3.13).
- FFmpeg и FFprobe. В проекте уже ожидаются файлы:
  - `tools/ffmpeg/ffmpeg.exe`
  - `tools/ffmpeg/ffprobe.exe`
- Python-зависимости из `requirements.txt` (включая yt-dlp, Pillow, psutil, argon2-cffi).

## Настройка

Скопируйте `.env.example` в `.env` и измените нужные значения. Основные параметры:

| Переменная | Назначение |
|---|---|
| `HOST`, `PORT` | Адрес и порт локального сервера |
| `ADMIN_PATH` | Скрытый префикс админ-панели |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Первичная учётная запись |
| `SECRET_KEY` | Ключ сессий; иначе создаётся `.secret_key` |
| `STORAGE_DIR`, `HLS_DIR`, `LOG_DIR` | Каталоги хранения, HLS и журналов |
| `FFMPEG_BIN`, `FFPROBE_BIN` | Пути к бинарникам |
| `OUTPUT_WIDTH`, `OUTPUT_HEIGHT`, `OUTPUT_FPS` | Параметры выходного потока |
| `VIDEO_BITRATE`, `AUDIO_BITRATE` | Битрейты HLS |
| `HLS_TIME`, `HLS_LIST_SIZE` | Длина сегмента и размер живого плейлиста |
| `PUBLIC_BASE_URL` | Внешний адрес для M3U/EPG |
| `ENGINE_ENABLED` | Автозапуск эфирного движка |

## Как устроен эфир

1. `video_engine.py` — единственный поток-супервизор. Он выбирает передачу по расписанию или в ротации.
2. `ffmpeg_manager.py` строит команду FFmpeg: сначала пытается COPY, при несовместимости переходит в TRANSCODE.
3. FFmpeg пишет HLS в `hls/stream/`. Отдельные запуски добавляют сегменты в один плейлист с `#EXT-X-DISCONTINUITY`, поэтому поток остаётся непрерывным для зрителя.
4. `stream_manager.py` отдаёт плейлист/сегменты и считает зрителей по heartbeat.
5. `scheduler.py` разворачивает расписание, повторяющиеся дни и синтетическую ротацию для EPG.

Публичный плеер использует hls.js (вендорная копия в `static/vendor/hls.min.js`) либо нативный HLS в Safari.

## Безопасность

- Панель не индексируется: `robots.txt` запрещает всё, публичные шаблоны не ссылаются на админ-путь.
- Пароли хранятся только как Argon2id-хеши.
- Все изменяющие запросы панели защищены CSRF-токеном.
- Сессия привязана к активности и истекает через заданное время.
- Загрузки проверяются по расширению, MIME и через FFprobe/Pillow.
- Внешние URL проходят проверку схемы, порта и защиту от SSRF.
- CSP разрешает только локальные скрипты; сторонние медиа допускаются только для предпросмотра.

## Docker и blitz.cloud

В репозитории есть `Dockerfile` для Linux-хостинга (например, blitz.cloud). Образ ставит FFmpeg/FFprobe из Debian, запускает приложение через waitress и хранит базу, загрузки, HLS и журналы в `/data`.

```bat
docker build -t simple-iptv .
docker run -p 5000:5000 -v simple-data:/data -e SECRET_KEY=change-me simple-iptv
```

Важно: приложение должно работать **в одном процессе**, потому что эфирный движок ровно один на процесс. Не запускайте несколько worker-процессов waitress/gunicorn с этим приложением.

Для blitz.cloud укажите в переменных окружения как минимум:

- `SECRET_KEY` — случайная строка;
- `ADMIN_PATH` и `ADMIN_PASSWORD` — свои значения вместо стандартных;
- `PUBLIC_BASE_URL` — публичный адрес приложения.

## Тесты

```bat
python -m pytest -q
```

Тесты используют временную SQLite-базу и не запускают эфирный движок (`create_app(start_engine=False)`). Проверяются модели, расписание, EPG, M3U, безопасность URL/путей, CSRF и публичные страницы.

## Ограничения

- Проект рассчитан на локальный запуск и не содержит конфигурации для развёртывания в интернете.
- Для YouTube и подобных сайтов требуется установленный yt-dlp и доступ к сети.
- При первом запуске без медиа канал показывает брендовую заставку ожидания.
- Аппаратное кодирование не включается автоматически: используется программный H.264/AAC для предсказуемой совместимости.
